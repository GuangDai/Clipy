## 方案

- 工作流使用常驻列表：每条独立命名、保存、选择触发方式和范围；列表从上到下就是自动执行优先级，可拖动调整。
- 编辑区采用有层级的步骤块。条件明确显示“如果 / 那么 / 否则”，分支内可以添加动作和条件；步骤支持拖动重排及键盘可用的移动操作。
- 工作流列表、步骤编辑和原文/结果对照分区。原文和结果使用相同宽度、字号、边距、左上对齐和换行规则的原生文本框；结果只读可复制。
- 删掉工作流中的“读取剪贴板”“选择图片”和随之失去用途的输入类型控件。运行时按每条工作流选择的来源读取；自动运行只处理新复制，不扫描旧历史。
- 同一次复制的工作流按列表优先级串行执行，各工作流都使用同一份固定输入。连续复制按到达顺序处理，不能用新事件静默覆盖等待中的事件。
- 手动和自动计算共用应用持有的执行队列。当前计算真正结束后才开始下一次，包括正在取消的原生 OCR。等待与运行状态分别显示；队列容量有界，拒绝时明确提示。
- 条件只控制所属分支；条件不匹配或某条工作流失败不阻断其他工作流。通知在选中分支完成后发送，预览不发送通知；自动工作流不隐式改写系统剪贴板。
- 面板和预览使用纯色背景，浅色为白色，深色跟随统一外观。文字外观改为可直接输入的字号与行数；菜单和设置使用一致的正文、说明、控件尺寸。

## 已确认的实现问题

- 旧结果区是 SwiftUI Text/ScrollView，左侧是 NSTextView，两侧布局体系不同。
- 旧自动执行器每次写入同一个 pending 槽，忙碌时中间复制会被覆盖。
- 旧鼠标模式切换前的进入事件被丢弃，离开时找不到进入记录，隐藏计时可能根本没有启动。
- 旧文字外观只提供有限枚举预设，不能输入实际字号与行数。
- PR #83、#84 已由用户合并；后续在 `master` 修正。
- 最新界面方向：列表使用 SwiftUI ScrollView/LazyVStack，预览文字及文件引用使用 SwiftUI Text；不再叠加原生表格选中背景或可选 NSTextField 的编辑布局。
