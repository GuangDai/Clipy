## 1. Executive summary

The production code under this module's umbrella — vendored xxh3, the Fuse-based SearchWorker, the adapter/UI scaffolds — is **sound**: xxh3 is correctly pinned and wrapped, the Fuse offset-alignment invariant is fail-safed, and ThumbnailService single-flight is correctly implemented (joins/dedupes flights, off-Authority worker, completed bytes not retained). The headline problem is **a construct-validity crisis in the certification apparatus, not the shipped code**: the §9 acceptance gate is unsatisfiable on master because wl8 times the end-to-end `store.thumbnail()` path, whose dominant cost is the actor-serialized `HistoryAuthority.thumbnailSource` prefix (8× before single-flight), so the gate can never pass and 5 calibration commits chasing it could not converge. One critical (gate-blocker), one major (measurement-design), and a long tail of minor/nit polish debt (median-helper contract violations, magic-number bounds with no encoded invariant, unenforced xxh3 integrity/KAT promises) round out the module. Fixing wl8 is the single highest-ROI change: rework the measurement to call `ThumbnailService.thumbnail` directly with pre-fetched source bytes, and decouple bullet 9 from the perf-proofs pass/fail until then.

## 4. Complexity analysis

| Function (file:line) | Current Big-O (time / space) | Notes | Reduction opportunity |
|---|---|---|---|
| `makeNoisePNG` raw-buffer fill (`main.swift:791-798`) | O(N) time / O(N) space, N≈3.15M | N is still ~3.15M individual `Data.append(byteGenerator.nextByte())` operations; extraction made the stream directly testable but did not change this constant-factor setup cost. Untimed, but on the CI-wall-clock path the recent commits were tuning. | One bulk fill: `[UInt8](unsafeUninitializedCapacity:)` or `UnsafeMutableBufferPointer`, inlined xorshift loop, bridge to `Data` once. Removes ~3M append-call overhead. |
| `crc32` over concatenation (`main.swift:766`) | O(N) time / O(N) extra space | Materializes a ~3MB `tagData+payload` Data copy just to feed crc32; the CRC itself is table-less bit-shift (8 iterations/byte over ~3MB ≈ 24M bit-iterations). | Incremental crc32 over `tagData` then `payload` sequentially (no concat) → O(1) extra space; 256-entry lookup-table CRC removes ~95% of per-byte work. Same output. |
| Pin-reorder population (`main.swift` pin workload, `:444`) | O(pinnedCount²) time / O(pinnedCount) space | Each `placePinned(.last)` call's `loadPinFacts` fetches+decodes ALL pinned rows. Untimed, small sizes (~40k ops at 200). | One bulk-pin transaction → O(pinnedCount). Revisit only if pin sizes scale. |
| `fuzzyMatch` count guard (`SearchWorker.swift:710`, fuzzy path) | O(N) per fuzzy row per query, ×2 | Full-throwaway `lowercased().count` copy (up to 5000 Chars) + Fuse's internal `_search` lowercase = 2N lowercasing passes. The guard is the offset-alignment proof linchpin, so it cannot simply be dropped. | Measure a fuzzy workload before optimizing. | `utf16PrefixOffsets` (`SearchWorker.swift:869`) | O(N) per matched title row + O(window) per body match | Full `[Int]` prefix-sum rebuilt on every matched title row and again over the `bodyExcerpt` window, just to translate a handful of Fuse ranges. ## 5. Efficiency notes

- **`makeNoisePNG` is a bounded setup optimization candidate, not a proven hotspot.** Its ~3.15M byte appends and table-less CRC are outside the timed construct, and current artifacts do not isolate their wall-clock share. Optimization is deferred until profiling meets the recorded trigger; the residual cost is runner-only.
- **`deterministicTextCapture` harness build is timed in wl1b.** The 1KiB/256KiB body `Data` is constructed INSIDE the `measureMedian` closure (`main.swift:333-340`), so String/Data construction is recorded alongside fingerprint+commit. Pre-building the body `Data` once per size outside the timed closure removes per-iteration harness allocation from the recorded median — a correctness-of-measurement gain, not a runtime gain (record-only workload, so no false gate).
- **`fuzzyMatch` count guard** allocates a full throwaway `String.lowercased()` of up-to-5000 Characters per fuzzy row per query (`SearchWorker.swift:710`). Retain its general Character-alignment proof until a replacement is proved over the supported Unicode runtime; U+0130 alone is not equivalent.
- **`utf16PrefixOffsets`** rebuilds a full O(N) `[Int]` prefix-sum per matched title row AND per `bodyExcerpt` window (`SearchWorker.swift:869`); lazy + reuse across lanes (see §4).
- **SearchWorker actor serialization** is a deliberate, spec-accepted throughput cap (corpus ≤5000), not a defect — leave for v2.

## 6. Security & edge-case notes

- **xxh3 NULL-input UB (latent).** `clipy_xxh3_64bits` forwards `(input,length)` to `XXH3_64bits` with no NULL guard (`xxh3.c:19`); `(NULL, n>0)` is UB per `xxhash.h:107`. The sole caller (`Data.withUnsafeBytes`) is safe today. Recommend a one-line precondition to match the codebase's fail-closed posture.
- **Supply-chain integrity gap.** VENDORED.md records pinned sha256 for `xxhash.h`/`.c` (v0.8.3) but no CI step recomputes/diffs them (`vendored-sha-not-reverified-in-ci`); the XXH3-64 KAT is a manual pre-landing check only (`xxh3-no-kat-test-in-suite`). A tampered, wrong-endianness, or wrong-secret re-vendor, or an accidental byte edit of the vendored blob, passes all current gates. A vendored C blob without automated integrity + KAT gates will silently drift on the next pin.
- **`hostName` PII leak remediated locally.** `MachineMetadata.hostName` was removed; fixtures now record non-PII architecture/hardware/processor facts. macOS probe/build proof remains.
- **`deterministicTextCapture` small-body contract drift (latent).** When `bodyBytes` < the `perf-item-<index>-` prefix length, the emitted body is the prefix alone (11+ bytes), violating the parameter's implied contract. No current caller requests small bodies (all use 64/1024/256KiB).
- **Fuse offset alignment now has a local regression.** The `lowercased().count==count` guard (`SearchWorker.swift:710`) makes a hypothetical count-shifting Unicode input a silent miss rather than a corruption. U+0130 is the important positive case: its lowercase form expands to two scalars but stays one Character, and WS17 now proves the returned UTF-16 range still indexes the original title. macOS proof is pending.
- **`safeRatio(0, positive)` returns 0.0** which trivially passes every finite bound (`main.swift:108`); the zero-denominator direction is guarded but the zero-numerator direction is not. Practically unreachable (attosecond resolution prevents a 0 measurement), but asymmetric.

## 7. Concurrency / isolation notes

- **The wl8 single-flight architecture is CORRECT; the proof is wrong.** `ThumbnailService.thumbnail` (`ThumbnailService.swift:141-177`) joins an existing in-flight decode for the exact key (`flights[key]`) or creates a new `Task` on the off-Authority worker actor; completed bytes are not retained (`defer { flights.removeValue(forKey:key) }`); only immutable `Sendable` values cross the actor boundary. `SwiftDataHistory.thumbnail` (`SwiftDataHistory.swift:388-403`), however, awaits `authority.thumbnailSource` (actor-isolated, `HistoryAuthority.swift:2129`) BEFORE calling `thumbnailService.thumbnail`. Eight concurrent `store.thumbnail()` calls therefore serialize 8× through the actor prefix before any single-flight can be observed — so `concTotal ≈ 8×seqMedian` regardless of decode cost. This is the construct-validity crisis: the production code needs no change; the proof apparatus does. Acting on the red gate by tuning the fixture (the path taken across 5 commits) cannot converge.
- **SearchWorker actor serialization** (`SearchWorker.swift:33`): `page()` and all `evaluate*` are non-suspending on an actor whose only mutable state is the non-Sendable Fuse matcher, so concurrent `browse(.search)` calls serialize the full O(corpus) scan even though the snapshot is Sendable and evaluation is pure. Throughput cap, not a correctness fault; spec accepts the ≤5000 corpus cap. v2 option: drop isolation, fresh Fuse per call.
- **wl2 has no deterministic teardown seam.** Reopening the same persistent SQLite URL relies on inner-scope ARC + a single `Task.yield()`; SwiftData exposes no `close()`/`teardown()` API. The runner therefore names the construct as best-effort warm repeated-open scaling and explicitly excludes cold-start, deterministic-teardown, and G5 absolute-latency claims. A future awaitable platform seam or observed variance is the trigger to revisit it.
- **Fixture structs are not `Sendable`** (`main.swift:42`) despite `PerfError: Error, Sendable` in the same file — inconsistent but no compile error today (no actor crossing).
